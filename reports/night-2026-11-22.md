## Piece 2 — start-screen exception

- **When it fires:** once per page load, at the first frame, when the window has no size yet —
  an embed at 0 height before layout, a tab not shown yet. `StartScreen.update`
  (`apps/client/src/start.ts` lines 23–24) sizes its canvas to `window.innerWidth` ×
  `innerHeight`, here 0; `drawStartScene` → `drawSky` → `drawBackdrop` builds a cached layer of
  that size, and the browser's `drawImage` throws on it.
- **What a player sees:** `frame` in `apps/client/src/main.ts` asks for the next frame only at
  its end, so the throw ended the frame loop: the start screen with "Joining the match …"
  stayed for good, also after the window got its size — the game never appeared. Reproduced in
  a browser (the client in a 0 × 0 iframe, resized after 3 s: no frame ran again).
- **Done:** the backdrop layers draw nothing on a canvas without a size
  (`packages/render/src/sky.ts` 181 → 192 lines: `drawLayer`, shared by `drawBackdrop` and
  `drawFrontClouds`, which repeated the same two lines); `sky.test.ts` new (55 lines), fails
  without the fix with the browser's error. No try/catch around the draw. The same browser case
  now runs on and the start screen fades. Client and all other suites green (452 tests).
- **Reused:** the layer cache `layer()` as it was; the render tests' way of stubbing `document`
  (`layers.test.ts`).
- **Noticed, left:** `frame` still stops for good on any other throw in a frame; the rule is a
