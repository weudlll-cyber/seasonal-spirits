# What a cheating or broken client can try

Every entry: what a client can send or do, the server's answer, and the test that proves it.
The rules behind it are in [CLAUDE.md](../CLAUDE.md) ("Server, clients, trust" and
"Security"). Test files: `protocol` = `packages/protocol/src/client-message.test.ts`,
`server` = `apps/server/src/server.test.ts`, `routes` = `apps/server/src/http-routes.test.ts`,
`core` = `packages/game-core/src/*.test.ts`.

The wire protocol carries hello, direction and the one action (`steal`, `secure`, `swap`).
The server checks only the message; whether an action does anything is decided by the game
core, which refuses every invalid action itself (rows 13–18), whoever sends it.

## Messages

| #   | A client tries                                                                   | The server's answer                                                                                                                            | Test                                                                                                                                                                      |
| --- | -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Text that is not JSON                                                            | Dropped by the shared validator (`parseClientMessage`); nothing is read from it                                                                | protocol "refuses anything that is not a JSON object"; server "survives garbage, null, arrays, numbers and wrong types without throwing"                                  |
| 2   | `null` — crashed the process before this fix (`msg.kind` on `null`)              | Dropped by the validator before any field is read                                                                                              | same two tests; the server test fails with the old code (uncaught `TypeError`, checked 2026-11-14)                                                                        |
| 3   | An array, a number, a string, `true`                                             | Dropped                                                                                                                                        | same two tests                                                                                                                                                            |
| 4   | An unknown `kind`; missing or wrong-typed fields                                 | Dropped                                                                                                                                        | protocol "refuses unknown kinds and missing or wrong-typed fields"                                                                                                        |
| 5   | `NaN`, `Infinity` (e.g. `1e400`), huge numbers, a direction component outside ±1 | Dropped; the core also treats a non-finite direction as standing still and clamps the magnitude to 1                                           | protocol "refuses Infinity, huge numbers and components outside [-1, 1]"; core `field.test.ts` "clamps an oversized direction to unit speed and ignores NaN and Infinity" |
| 6   | Extra fields: a position, a coin count, a value, a team                          | Never read: the validator returns a fresh object with the known fields only                                                                    | protocol "accepts the three valid messages and returns only their known fields"; server "ignores a position, count or team sent along with an input"                      |
| 7   | `__proto__` to smuggle in a `kind`                                               | Dropped: `JSON.parse` makes it an own property, which is not `kind`                                                                            | protocol "does not let \_\_proto\_\_ smuggle in a kind"                                                                                                                   |
| 8   | A binary frame, even with a valid input inside                                   | Ignored; clients speak JSON text                                                                                                               | server "ignores binary frames, even a valid input in one"                                                                                                                 |
| 9   | An oversized message                                                             | The WebSocket server refuses frames above 256 bytes (`maxPayload`, close code 1009); the validator also checks the length                      | server "closes a socket that sends a frame above the size bound"; protocol "refuses a message longer than the bound before parsing it"                                    |
| 10  | A flood above the rate limit                                                     | Every message, valid or not, counts against `maxInputsPerSecond` (20); the rest of the second is dropped                                       | server "drops messages above the per-second rate"                                                                                                                         |
| 11  | A second hello, or switching from player to spectator                            | Ignored; the first hello decides                                                                                                               | server "keeps a player a player after a second hello"                                                                                                                     |
| 12  | A spectator sending inputs (or anything) after its hello                         | The connection is closed (1008)                                                                                                                | server "closes a spectator that sends anything after its hello"                                                                                                           |
| 12a | An action that is not steal, secure or swap                                      | Dropped by the validator                                                                                                                       | protocol "accepts the three actions and nothing else as an action"                                                                                                        |
| 12b | Joining when every slot has a player                                             | The client becomes a spectator and is told so (`{"kind":"spectating","reason":"full"}`); anything it sends afterwards closes it (1008, row 12) | server "makes a late player a spectator when every slot has one, and closes it if it sends"                                                                               |

## Game actions (enforced by the game core)

| #   | A client tries                                                                          | The core's answer                                                                                                                         | Test                                                                                                                                              |
| --- | --------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 13  | Swap away from the own shrine, or at another team's                                     | Nothing happens                                                                                                                           | core `actions.test.ts` "is refused away from the own shrine and at another team’s shrine"                                                         |
| 14  | Swap with fewer than `swapMinIn` (6) coins of the current season, or in the last season | Nothing happens                                                                                                                           | core "is refused with fewer than swapMinIn (6) coins of the current season"; `rules.test.ts` "neither offers nor makes a swap in the last season" |
| 15  | Secure away from the own shrine, or with nothing                                        | Nothing happens                                                                                                                           | core "is refused away from the own shrine and with nothing carried"                                                                               |
| 16  | Steal out of range, from a teammate, from itself                                        | Nothing happens; the target is chosen by the core (nearest opponent carrier)                                                              | core "does nothing out of range", "never takes from a teammate", "never takes from the thief itself"                                              |
| 17  | Steal every tick                                                                        | One steal per cooldown (1 s, placeholder)                                                                                                 | core "waits for the cooldown before the next steal"                                                                                               |
| 18  | Move faster or through the wall                                                         | Speed comes from the config, the position is clamped to the field                                                                         | core "a carrier moves slower by the configured factor", "never leaves the field"                                                                  |
| 18a | Shove other ghosts (out of a shrine, off the field)                                     | Separation is soft and symmetric (half the overlap each, bounded by the radius); a securing ghost is never moved; nobody leaves the field | core `separation.test.ts` "never moves a ghost while it secures", "never pushes a ghost out of the field"                                         |

## The other direction: server frames in a client

| #   | A broken or forged server frame                                                                                                       | The client's answer                                                                                                                                                                                                                                                                                                                                                 | Test                                                                                                                                                                                                                                                                                              |
| --- | ------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 27  | A text frame that is not a welcome or the spectating notice, or one with out-of-range fields                                          | Dropped by the shared reader `parseServerMessage`; the client reads no field of it                                                                                                                                                                                                                                                                                  | `packages/protocol/src/server-message.test.ts` "drops non-JSON, non-objects, other kinds and out-of-range fields"                                                                                                                                                                                 |
| 28  | A binary frame of the wrong length                                                                                                    | `decodeState` throws before reading past the header; the frame is not shown                                                                                                                                                                                                                                                                                         | `packages/protocol/src/state.test.ts` "rejects a corrupted length"                                                                                                                                                                                                                                |
| 29  | A forged steal notice (a ghost out of range, no coins, a thief robbing itself) — or a client hoping to learn of steals between others | `parseServerMessage` drops anything but two different ghost ids 0–255 and coins 1–65535; the server sends a notice only to the two players involved, never to spectators, bots or anyone else, and only for the tick it happened (none during the result pause)                                                                                                     | `server-message.test.ts` "reads a steal notice with only its known fields", "drops a steal notice with a ghost out of range, no coins, or a thief robbing itself"; `match-host.test.ts` "tells a player robbed by a bot, and only that player", "sends no notice to anyone for steals among bots" |
| 30  | Reading more from the "can steal" flag (`GHOST_CAN_STEAL`) than the screen shows                                                      | It says only whether a steal would take something now — derived from public positions, coin counts and the thief's own cooldown (core `canSteal`, the same check `trySteal` makes); it sits in the existing flags byte, the state size is unchanged                                                                                                                 | `match-host.test.ts` "lights the Steal flag only while a steal would take something, and tells the thief"                                                                                                                                                                                         |
| 31  | Reading more from the shield flag (`GHOST_SHIELDED`) than the screen shows, or a forged one                                           | It says only whether a ghost carries swapped coins that no steal can take until the next halving — what the shield on screen shows, derived from the public swap; the core decides every steal on its own (`isStealTarget`), so a forged or flipped bit in a frame changes nothing but the drawing; it sits in the existing flags byte, the state size is unchanged | `packages/protocol/src/state.test.ts` "keeps every ghost flag, the shield included, through a round trip"; `match-host.test.ts` "marks a carrier of swapped coins, keeps Steal dimmed against it, until the halving"                                                                              |

The client sends no new kind of message: the hello, a direction and the one action, all
through `parseClientMessage` on the server (rows 1–12a). New server → client: the steal
notice (row 29), the "can steal" flag (row 30) and the shield flag (row 31).

## Open

- Behind the website's nginx every connection comes from the proxy's address, so the
  per-address bound (row 20) must use the forwarded client address from the trusted proxy once
  the game runs embedded (backlog g).
- Without the website sign-in a returning player cannot be recognised: a reconnect is a new
  player, and the old ghost stands for the grace time before a bot takes it (backlog g).
